# Git

## Who commits

The author is the only person who runs `git commit` and `git push`, and the only author and contributor in the history. Any assistant or tool working in this repository edits files and then hands over the exact commands to run. It never commits or pushes, and never adds `Co-authored-by`, `Generated by` or similar lines to commits, files or pull requests.

## What is committed

| Committed | Never committed |
|---|---|
| `src/`, `scripts/`, `configs/`, `tests/`, `analysis/` | `drive/`, the local mirror of Drive |
| `notebooks/`, with outputs cleared | data of any kind, raw or processed |
| `conventions/`, `docs/`, `readme.md`, `pyproject.toml`, `.gitignore` | full run folders, model checkpoints |
| `results/`, small tables and final figures used in the paper | tokens, `.env` files, credentials |
| | personal tool and assistant configuration files |

Personal tool files are kept out through `.git/info/exclude`, which is local to the machine and never pushed, so the committed `.gitignore` does not name them either.

## Before every commit

```bash
git status
git diff --stat
pytest -q
```

Check that `git status` lists nothing from the right-hand column above.

## Commit messages

One line, lowercase, present tense, saying what changed: `add clopper pearson bounds`, `fix window assignment for ugr16`. When a commit produced the code for a run that matters, the run folder records its hash in `meta.json`, so the message does not need to.

## Branches

Work on `main` while the project is small. Use a branch for anything that might be thrown away, and pass its name to the runner notebook through `BRANCH`.
